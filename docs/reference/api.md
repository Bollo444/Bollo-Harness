# Optional local API and endpoint documentation

**PROPOSED P2, NOT IMPLEMENTED, NOT REQUIRED FOR MVP.**
Canonical contract: [OpenAPI 3.1 JSON](../contracts/openapi.json).
Example DTOs: [api.json](../examples/api.json). This API is Bollo's original facade;
it is neither Claude Code's API nor Grok's ACP or tools gRPC interface.

## Deployment, identity and auth

Prefix `/v1`; proposed local default `http://127.0.0.1:7777`. Every route including
health requires a bearer token. Token is generated by trusted local operator action,
stored privately and bound to a configured workspace plus explicit capabilities.
No arbitrary filesystem root in CreateSession; it inherits the daemon-bound workspace.
No token in URL/query, no cookie-based authorization and no wildcard CORS. Validate
Host and Origin; enforce TLS for remote exposure and a reviewable origin allowlist.
Resource IDs are checked against token/workspace scope; foreign resources return 404.
Rate limit proposed default: 60 control requests/minute per token, 5 concurrent event
streams, 1 active run per session. These are configurable operational targets.

API bearer access can read sensitive session data and authorize actions. Only tokens
explicitly granted `approve` may consume approvals. Read-only viewer tokens cannot
start/cancel runs or approve. Host unrestricted startup is not enabled by an API
request; it remains a local operator decision at daemon launch.

## Endpoint catalog

| Method / path (under /v1) | Request | Success | Auth capability | State/errors |
|---|---|---|---|---|
| GET /health | none | 200 Health | read | no secrets; 401/403 if unauthorized |
| GET /capabilities | none | 200 Capabilities | read | actual sandbox/features, not assumptions |
| POST /sessions | CreateSession `{label?}`; Idempotency-Key | 201 Session | run | uses daemon workspace; mismatch key/body 409 |
| GET /sessions/{session_id} | path ID | 200 Session | read | unknown/foreign 404 |
| POST /sessions/{session_id}/runs | `{prompt}`; Idempotency-Key | 202 Run | run | one active run; busy 409 |
| GET /runs/{run_id} | path ID | 200 Run | read | terminal state remains readable |
| POST /runs/{run_id}/cancel | no body | 202 CancelResult | run | idempotent; terminal state remains unchanged |
| GET /sessions/{session_id}/events | after or Last-Event-ID cursor | 200 SSE Event stream | read | old cursor 410; ahead-of-log or inconsistent cursors 400 |
| GET /approvals/{approval_id} | path ID | 200 Approval | approve | complete command/diff view, scope and rule source; no secret values |
| POST /approvals/{approval_id}/decision | ApprovalDecision | 200 ApprovalResult | approve | expired 410; consumed/stale/hash mismatch 409 |
| GET /runs/{run_id}/artifacts | path ID | 200 Artifact[] | read | metadata only |
| GET /artifacts/{artifact_id} | path ID | 200 text/plain | read | bounded redacted tool text only; private/binary artifact unavailable 404 |
| GET /sessions/{session_id}/policy | path ID | 200 Policy | read | effective rules, revision and rule provenance |

Before deciding, approval clients fetch the complete Approval view; the event summary is
not sufficient for consent. If display cannot fit the bounded view, block the action
and ask for smaller operations, never approve an undisclosed truncated command/diff.
HTTP request bodies cap at 1 MiB; approval response bodies cap at 4 MiB encoded.

No raw exec endpoint, unauthenticated webhook, browser cookie session or write-policy
endpoint is included. Setting permissions through an HTTP JSON body is not a shortcut
to bypass the local trust flow.

## Creation and idempotency

Create calls require an opaque Idempotency-Key of 16–128 characters. Persist key,
request body hash and response atomically, scoped to token principal + route for 24h.
Same key/body returns original response and IDs; same key/different body = 409. Persisted
receipts survive daemon restart. After expiry a retried creation may create a new resource;
clients must not assume indefinite exactly-once effects. Cancel is naturally idempotent.
Approval decisions are once-only and return conflict on duplicate consumption.

## Streaming and reconnection

A run request returns 202 promptly, not after inference. Subscribe to session events;
SSE event ID is the numeric session sequence. If `after` and Last-Event-ID are both
supplied they must agree. A cursor beyond current last_seq is invalid. Retained events
replay before live events; deduplicate by event_id. Slow clients are disconnected after
bounded buffering, never allowed to block tool journaling. A viewer disconnect does
not cancel the run; cancellation is explicit. See [events](events.md).

## Error catalog

Error object: `{code, message, request_id, retryable}`. Keep HTTP status separate from
runtime tool errors, which appear inside run events/results.

| HTTP | Codes | Client action |
|---|---|---|
| 400 | invalid_request, invalid_cursor, invalid_tool_arguments | Fix input; no blind retry |
| 401 | unauthenticated | Provide/rotate supported local token |
| 403 | forbidden, origin_denied | Inspect token grants/origin policy |
| 404 | not_found | Resource absent or outside authorized scope |
| 409 | session_busy, idempotency_conflict, approval_stale, approval_consumed | Fetch current state; no repeat effect |
| 410 | cursor_expired, approval_expired | Obtain fresh metadata/approval |
| 429 | rate_limited | Honor Retry-After and bounded backoff |
| 500 | internal_error, storage_unavailable | Stop mutations; diagnose with request ID |

Additional run/tool reasons include approval_required, pricing_unknown, budget_exceeded,
run_limit_exceeded, preimage_conflict, sandbox_unavailable and operation_unknown.
OpenAPI declares common errors on all operations as a conservative shared envelope;
operation-specific errors above define expected normal failures.

## Request example (future server)

```http
POST /v1/sessions/ses_01/runs HTTP/1.1
Authorization: Bearer <local-scoped-token>
Idempotency-Key: 0123456789abcdef
Content-Type: application/json

{"prompt":"Fix the parser and run its tests."}
```

```json
{"id":"run_01","session_id":"ses_01","state":"queued","created_at":"2026-10-03T20:00:00Z","reason":null}
```

These IDs are examples, not live services. Browser preview clients must use relative
URLs through the preview server, never hardcoded localhost against a remote sandbox.

## Compatibility and completeness

The document covers every endpoint in the proposed OpenAPI contract. It does not
pretend to list every private endpoint inside upstream products. Tool outputs and
full future ACP/remote OAuth details need further conformance work before P2 release.
API DTO fields and schema references are validated now; server behavior is not.
